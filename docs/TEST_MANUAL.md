# 数字孪生视频融合：逐步骤测试实操手册 (`TEST_MANUAL.md`)

本手册配合 `dt-video-fusion-pro-v3` 工程使用，涵盖从环境启动、6 大核心功能练习、Python OpenCV 标定联调到常见报错排查的完整操作步骤与推荐参数。

---

## 一、环境准备与启动自检

### 1. 前端启动
确保本地已安装 **Node.js v18+**，在项目根目录执行：
```bash
npm install
npm run dev
```
启动后用 Chrome / Edge 访问终端输出的本地地址（默认 `http://localhost:5173`）。

### 2. 启动自检标准
页面打开后应立刻看到：
- 3D 工业园区场景（深灰地面、后方主厂房、左侧配电室、前排棕色立柱与绿色设备箱）。
- 3 个带彩色边框和扫描线的动态测试画布投影在场景中（`CAM_FIXED_01` 青色、`CAM_FIXED_02` 橙色、`CAM_PTZ_03` 紫色）。
- 左上角状态栏显示：`当前激活槽位: 3 / 4 (池总数: 3)`。

## 二、6 大实操练习逐步骤指南

### 练习 1：多路视频投影、PCF 软遮挡与去掠射角拉伸
**目标**：掌握双通道深度遮挡防穿模、PCF 3×3 边缘柔化，以及侧墙法线衰减消除拉丝感。

1. **上传本地视频**：在左上角「练习 1：上传本地视频（替换 1 号枪机）」中选择一个符合规范的 `.mp4`（H.264）文件，观察视频实时投射到厂房和地面上。
2. **验证防穿模（深度遮挡）**：
   - 拖动鼠标左键，将视角旋转到**前排棕色立柱的后方**（看向主厂房墙面）。
   - 在右上角 GUI 展开「练习 1：投影画质、PCF 与去拉伸」，**取消勾选「开启深度遮挡」**。
   - *预期现象*：视频直接“穿透”立柱，错误地印在立柱背后的主厂房墙面上。
   - **重新勾选「开启深度遮挡」**：立柱背后的墙面立刻恢复正常阴影，不再出现穿模画面。
3. **验证 PCF 3×3 软边缘与 Bias**：
   - 拉近视角观察立柱在主厂房上投下的遮挡边缘，反复切换 **「PCF 3×3 软边缘」**，对比硬锯齿与柔和过渡的差异。
   - 将 **「深度偏移 Bias」** 拖到最小 `0.0001`，观察表面是否出现斑马纹（Shadow Acne）；回调至推荐值 **`0.0020 ~ 0.0030`** 斑马纹消失。
4. **验证消除侧墙拉丝（掠射角淡出）**：
   - 将视角转到主厂房或立柱的**侧面**（与投影相机视线几乎平行的面）。
   - 将 **「掠射角淡出阈值」** 拖到 `0.0`，可见侧墙上的视频被严重拉长变形；拖回推荐值 **`0.12 ~ 0.25`**，侧墙拉伸画面自然淡出。

### 练习 2：广角镜头畸变矫正与画质调色
**目标**：理解 OpenCV 正向畸变映射原理，并通过独立色彩参数消除视频的“贴纸感”。

1. 展开右上角 GUI「练习 2 & 4：相机微调与 JSON 导出」，确认「选中相机」为 `cam_fixed_01`。
2. **测试广角畸变**：
   - 拖动 **「径向畸变 k1」** 至 `-0.35`（模拟桶形广角监控）或 `+0.30`（模拟枕形畸变）。
   - *预期现象*：投影在墙面上的测试网格边缘产生明显弯曲，但立柱的深度遮挡边界依然严丝合缝（因为深度图用理想针孔 UV，视频采样用畸变 UV）。
3. **色彩匹配调优**：
   - 依次微调 **画面亮度**（如 `-0.08`）、**画面对比度**（如 `1.15`）、**画面饱和度**（如 `0.85`），观察视频画面如何更好地融入 PBR 场景光影。

### 练习 3：球机（PTZ）平滑巡航与光学变焦联动
**目标**：体验云台延迟对齐缓冲队列、光学变焦与局部单槽位深度图更新。

1. 展开右上角 GUI「练习 3：球机 PTZ 巡航与光学变焦」。
2. 勾选 **「开启球机自动巡航(含变焦)」**。
3. *预期现象*：
   - 位于园区中央高处的 3 号球机视锥体（紫色测试画布）开始平滑左右扫动并周期性拉近/拉远（Zoom）。
   - 变焦拉近时，投影范围缩小、画面变清晰，同时 `PTZController` 自动联动更新了 `FOV`、`fx/fy` 并按变焦比例衰减了广角畸变系数。
   - 拖动 **「视频延迟补偿(ms)」**（如调至 `600`），可模拟匹配真实 WebRTC 流的延迟对齐效果。

### 练习 4：3D 控制点采集、Python `solvePnP` 标定与 JSON 热重载/导出
**目标**：跑通从真实监控视频到 Three.js 精准空间配准的完整闭环。

#### 方式 A：纯前端可视化微调 + 导出热重载（适合现场快速精调）
1. 在 GUI「练习 2 & 4：相机微调与 JSON 导出」中选中任意相机，微调其 `位置 X/Y/Z`、`Yaw/Pitch/Roll`、`FOV` 和畸变参数。
2. 点击 **「一键导出 park_cameras.json」**，浏览器会自动下载最新配置文件（内置 Three.js 列优先转行优先的 4×4 `matrixWorldRowMajor` 矩阵）。
3. 刷新页面或点击左上角 **「练习 4：热重载相机配置 JSON」** 上传刚才导出的文件，无需重启服务即可还原微调后的精确位姿。

#### 方式 B：Python OpenCV 真实标定全流程（适合真实监控接入）
1. **采集 3D 点**：在 Three.js 场景中，按住 **`Shift` + 鼠标左键**，依次点击 6~8 个**不共面**的清晰特征点（例如主厂房四角 + 前排立柱顶点 + 设备箱角点）。点击左上角 **「复制 Python 数组」**。
2. **安装 Python 依赖**：
   ```bash
   cd python-tools
   pip install -r requirements.txt
   ```
3. **（可选）标定镜头内参**：录制一段 10~15 秒的棋盘格视频，运行：
   ```bash
   python calib_toolkit.py intrinsics --video chess.mp4
   ```
   获取精确的 `K` 与 `dist`（RMS 重投影误差 `< 0.5 px` 为优秀），可用 `python calib_toolkit.py verify --video cam01.mp4` 肉眼检验边缘直线是否拉直。
4. **采集 2D 像素点**：运行以下命令，**严格按照刚才 3D 点的相同顺序**在视频画面上点击对应位置，按 `Enter` 输出 `pts_2d`：
   ```bash
   python calib_toolkit.py pick2d --source cam01.mp4
   ```
5. **求解 PnP 并写入 JSON**：打开 `python-tools/calib_toolkit.py`，将底部 `K_demo`、`dist_demo`、`pts_3d_demo`、`pts_2d_demo` 替换为你的真实数据，运行：
   ```bash
   python calib_toolkit.py pnp
   ```
   终端输出平均重投影误差（建议 `< 2.0 px`），并自动更新 `public/config/park_cameras.json`。刷新浏览器即可看到精准贴合效果。

### 练习 5：自定义 Draco GLB 模型与 30 路大园区动态调度
**目标**：验证外部园区模型接入、显存防泄漏及多路监控的视锥体剔除调度。

1. **上传自定义 GLB**：保持左上角「上传后自动居中落底并适配视角」为勾选状态，上传你本地的 `.glb` 园区模型（详细导出规范见 `docs/ASSET_REQUIREMENTS.md`）。观察旧场景自动销毁、新模型自动居中并承接视频投影。
2. **30 路动态调度压测**：
   - 在 GUI 展开「练习 5 & 6：30路调度与 AI 闭环」，勾选 **「注入 27 路虚拟监控(共30路)」**。
   - 拖动鼠标在园区四周旋转、平移、拉近视角，同时观察左上角绿色状态栏。
   - *预期现象*：逻辑监控池总数变为 `30`，但物理激活槽位始终被严格控制在 **`<= 4 / 4`**，确保 WebGL 纹理单元不溢出且保持高帧率。

### 练习 6：YOLO 2D 反投影、跨镜去重、尾迹与 3D 电子围栏告警
**目标**：验证单目射线反投影与多摄像头重叠区 3D 空间聚类去重闭环。

1. 在 GUI「练习 5 & 6：30路调度与 AI 闭环」中，同时勾选 **「开启模拟 YOLO 跨镜追踪」** 和 **「显示 3D 电子围栏」**。
2. *预期现象*：
   - 园区地面出现一个青色半透明 3D 围栏，以及一个带头顶 `#1 PERSON` 悬浮标签和绿色地面运动尾迹的目标圆柱。
   - 该目标往返穿越 1 号和 2 号枪机的重叠视野区，虽然两路相机各自上报了不同局部 ID（`101` 和 `202`），但经过 `MultiCamTracker3D` 加权聚类后，场景中始终只有 **1 个平滑目标（无双影）**，且全局 ID 保持 `#1` 不变。
   - 当目标走入中央电子围栏内部时，围栏瞬间变为**红色**，头顶标签切换为 `#1 越界告警!`，页面顶部弹出红色呼吸告警横幅。

## 三、常见报错与排查清单

| 现象 / 报错 | 常见原因 | 解决方案 |
| :--- | :--- | :--- |
| 上传本地视频后投影区呈**纯黑**或无画面 | 视频编码为 H.265 (HEVC) 或 10-bit，浏览器无法解码 | 使用 `docs/ASSET_REQUIREMENTS.md` 中的 FFmpeg 命令转为 H.264 + `yuv420p` |
| 上传 `.glb` 后模型**完全黑屏**或控制台报 Shader 编译错误 | 模型使用了 Unlit（无光照）材质，缺少 `objectNormal` | 在 Blender 中改为 `原理化 BSDF (Principled BSDF)` 标准 PBR 材质重新导出 |
| 上传 `.glb` 后**某面墙死活投不上视频** | 该墙面法线贴反（朝向建筑内部），被掠射角算法剔除 | 在建模软件中重新计算外向法线，或临时将「掠射角淡出阈值」调低验证 |
| 离线/内网环境加载 Draco 压缩的 `.glb` 失败 | 默认 `DRACOLoader` 指向了在线 CDN | 导出时不勾选 Draco 压缩，或将 `node_modules/three/examples/jsm/libs/draco/` 复制到 `public/draco/` 并修改 `src/main.js` 中的解码器路径 |
| `npm install` 安装极慢或超时 | 默认 npm 源网络波动 | 执行 `npm install --registry=https://registry.npmmirror.com` |
| `solvePnP` 算出的相机位置飞到天外或误差 > 10px | 选点共面（全在同一面墙）、2D/3D 点顺序错位或广角畸变未标定 | 重新采集立体分布的 6~8 个点，严格核对 `#1~#6` 对应顺序，广角镜头先做棋盘格内参标定 |
